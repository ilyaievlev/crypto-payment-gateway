# Платёжный шлюз Crypto Payment Gateway

## Локальный TRON-кошелёк

Для первого запуска выполни `make vault-init`. Команда поднимет PostgreSQL,
применит миграции, создаст парольный файл в `.secrets/` с правами `0600` и
инициализирует TRON-кошелёк. Recovery-фраза из 12 английских слов появится в
терминале только при успешном первом создании. Сохрани её офлайн: она даёт полный
доступ к средствам и повторно приложением не показывается.

Корневой BIP-39 seed хранится в PostgreSQL только в виде AES-256-GCM ciphertext.
Случайный ключ данных хранится в Docker volume `crypto-vault-key-data`, завёрнут
паролем через Argon2id. Пароль находится отдельно в `.secrets/vault-password`;
оба локальных пути исключены из Git. Для восстановления сервиса нужны резервная
копия БД, key volume и парольный файл. Recovery-фраза позволяет восстановить
кошелёк в совместимом TRON-кошельке отдельно от этих резервных копий. Для
восстановления seed внутри Crypto Vault потребуется отдельная команда импорта;
сейчас она не входит в этот первый этап.

`chain-worker` подключается к Nile по адресу `https://nile.trongrid.io`. Для
проверки доступа к текущему блоку запусти `make test-tron-nile`. Тест только читает
состояние сети и не отправляет транзакции. Публичный endpoint можно переопределить
через `TRON_NILE_ENDPOINT`; личный `TRON_NILE_API_KEY` задаётся локально в `.env`.

После инициализации кошелька сервисы запускаются командой `make apps`.

## Сквозной приём TRX в Nile

`payment-core` создаёт инвойс с отдельным HD-адресом, `crypto-vault` выводит адрес
из индекса без раскрытия ключа, а `chain-worker` сканирует только solidified-блоки
Nile. Переводы сначала атомарно сохраняются вместе с курсором индексации, поэтому
повторный проход после перезапуска не теряет и не удваивает поступления. Статус
`paid` появляется, когда сумма финализированных поступлений достигает суммы инвойса.

Создай инвойс, указав сумму в sun (1 TRX = 1 000 000 sun):

```sh
curl -sS http://127.0.0.1:8081/v1/tron/invoices \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: order-1001' \
  -d '{"amount_sun":"1000000"}'
```

В ответе будут `id`, `address`, `expected_amount` и начальный `status`. Проверь
поступления запросом `GET /v1/tron/invoices/{id}`. Можно также задать
`TRON_START_BLOCK` в `.env`, чтобы начать индексировать с указанной высоты; пустое
значение начинает с текущей финализированной высоты при первом старте worker-а.
Курсор хранится в PostgreSQL и при перезапуске не сбрасывается.

Сейчас прикладной инвойс принимает TRX. Индексатор уже выделяет TRC-20 события,
но поддержка токенов в инвойсах и вывод средств ещё не включена.
